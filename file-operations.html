File Operations

Java has two generations of file APIs. Interviews expect you to know the modern one and recognise the old one.

  • Legacy (Java 1.0+): java.io — the File class and stream/reader classes.
  • Modern (Java 7+): java.nio.file — Path, Paths, and the Files utility class. Prefer this in new code.

The two building blocks (NIO)

  • Path — represents a location (file or directory). It's just a path; the file may or may not exist.
  • Files — a utility class of static methods that actually *do* things (read, write, copy, delete...).
Java
import java.nio.file.*;

Path path = Path.of("data", "notes.txt");   // data/notes.txt (OS-independent)

Create / check / delete

Java
Files.exists(path);                 // true if it exists
Files.createFile(path);             // create an empty file (fails if it exists)
Files.createDirectories(Path.of("data/logs"));  // create dir + parents
Files.delete(path);                 // throws if missing
Files.deleteIfExists(path);         // safe: no exception if missing
Files.size(path);                   // bytes

Writing text

Java
// write (creates or TRUNCATES the file)
Files.writeString(path, "Hello\nWorld");

// append instead of overwriting
Files.writeString(path, "\nmore", StandardOpenOption.APPEND);

// write many lines
Files.write(path, List.of("line1", "line2"));

Reading text

Java
String all = Files.readString(path);        // whole file as one String (small files)
List<String> lines = Files.readAllLines(path);// list of lines (small files)

// large files: stream lines lazily, don't load everything into memory
try (Stream<String> s = Files.lines(path)) {
    s.filter(l -> l.contains("ERROR")).forEach(System.out::println);
}
  • readString / readAllLines load the entire file into memory — fine for small files, dangerous for huge ones. Use Files.lines() (a lazy stream) for large files.

Copy / move

Java
Files.copy(src, dest, StandardCopyOption.REPLACE_EXISTING);
Files.move(src, dest, StandardCopyOption.REPLACE_EXISTING); // move or rename

Listing a directory

Java
try (Stream<Path> entries = Files.list(dir)) {          // one level
    entries.forEach(System.out::println);
}
try (Stream<Path> tree = Files.walk(dir)) {             // recursive
    tree.filter(Files::isRegularFile).forEach(System.out::println);
}

try-with-resources — the non-negotiable habit

Anything that opens a file/stream must be closed, or you leak OS file handles. try-with-resources closes it automatically, even if an exception is thrown.

Java
try (BufferedReader br = Files.newBufferedReader(path)) {
    String line;
    while ((line = br.readLine()) != null) {
        System.out.println(line);
    }
}   // br.close() called automatically here
  • Any resource implementing AutoCloseable works with try-with-resources.
  • This is the modern replacement for closing streams in a finally block.

Streams: bytes vs characters

  • Byte streams — InputStream / OutputStream — for binary data (images, PDFs, any raw bytes).
  • Character streams — Reader / Writer — for text (handle character encoding like UTF-8).
  • Buffered wrappers (BufferedReader, BufferedInputStream) add an in-memory buffer so you hit the disk far less often — a big speed-up. (This is the Decorator pattern in action.)
Java
// classic legacy style (still very common in interviews)
try (BufferedReader br = new BufferedReader(new FileReader("notes.txt"))) {
    ...
}

Legacy File vs modern Path/Files

TaskLegacy java.io.FileModern java.nio.file
Represent a locationnew File("a.txt")Path.of("a.txt")
Check existencefile.exists()Files.exists(path)
Deletefile.delete() (returns boolean)Files.delete(path) (throws on failure)
Read all linesmanual loop with a readerFiles.readAllLines(path)
Error reportingboolean returns (easy to ignore)real exceptions (harder to ignore)
  • Prefer Path + Files: clearer errors (exceptions instead of silent false), richer methods, and better cross-platform behaviour.

Common gotchas

  • Forgetting to close a stream → leaked file handles; always use try-with-resources.
  • Files.readString / readAllLines on a multi-GB file → OutOfMemoryError; stream it with Files.lines().
  • Files.delete() throws if the file is missing; use deleteIfExists() when "already gone" is acceptable.
  • Hard-coding path separators ("data\\notes.txt") breaks across OSes; use Path.of("data", "notes.txt").
  • Not specifying a charset when reading/writing text can cause garbled output; the NIO Files text methods default to UTF-8.
